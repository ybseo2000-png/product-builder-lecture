# 실제 데이터 연계 절차

## 초기 조사 상태 (후속 NKIS 업데이트는 아래 링크 참조)

NKIS 공식 명세 확인 및 수집 코드가 추가됐습니다. 최신 상태와 사용자 절차는 [NKIS 설정 안내](NKIS_SETUP.md)를 확인하세요. 아래 접속 실패 기록은 최초 조사 당시 결과이며 현재 NKIS는 접속됩니다.

## 초기 상태 (2026-10-21)

- 웹페이지는 data/research.json, data/bids.json을 fetch로 읽습니다.
- 두 파일 모두 status=pending이며 실제 수집 자료가 아닙니다.
- 공식 사이트 및 API 서버 접근은 클라우드 네트워크 정책으로 차단됐습니다 (프록시 403).
- 공식 API 명세, 과거 자료 보유 범위, 호출 제한, 연구기관 과제 API 제공 여부는 아직 확인하지 못했습니다.
- 인증키가 없으며 실제 API 호출 및 수집은 검증되지 않았습니다.

## 사용자: 공공데이터포털 신청

1. https://www.data.go.kr 에 로그인합니다.
2. `조달청 나라장터 입찰공고정보서비스`를 검색합니다. 서비스 명칭이 변경됐을 수 있으므로 제공기관이 조달청인지, 현행 서비스인지 확인합니다.
3. 서비스 상세에서 용역 입찰공고 목록과 업종 제한/참가자격 정보를 제공하는지 확인합니다. 목록 API와 참가자격 API가 다를 수 있습니다.
4. 활용신청에서 웹사이트에 공개 가능한 입찰공고 조회 목적을 기재합니다. 이용 조건, 자동/심의 승인 여부, 개발·운영 트래픽 한도를 확인합니다.
5. 승인 후 제공되는 상세 페이지 주소와 API 명세를 확인합니다. 채팅에는 서비스 상세 페이지 주소와 승인 여부만 전달합니다. 인증키 및 키가 포함된 요청 URL은 전달하지 않습니다.
6. 실제 수집 서비스가 결정되면 GitHub 저장소 Settings → Secrets and variables → Actions에 수집 작업용 Repository secret을 등록합니다. 정확한 secret 이름과 작업 파일은 명세 확인 후 제공합니다. 현재 자동 수집 workflow는 없습니다.

GitHub Actions에서 수집한다면 키는 Actions secret에 보관합니다. 클라우드에서 직접 테스트하려면 별도 클라우드 secret 바인딩이 필요하며, 저장 위치가 서로 다릅니다. 브라우저 JavaScript, 공개 JSON, Git에는 인증키를 넣지 않습니다.

## 개발: 나라장터 수집 검증 순서

1. 현행 HTTPS 엔드포인트 및 파라미터, 인증키 인코딩 방식 확인.
2. 짧은 기간 1페이지 호출로 정상 코드와 응답 구조 검증.
3. 공고기관 필드와 수요기관 필드를 구분. 공고기관명이 정확히 문화체육관광부인 공고를 선택.
4. 투찰가능업종 코드 1169 포함 여부 확인. 제목에 '연구'가 들어간다는 이유로 대체하지 않음. 여러 업종인 경우 코드 배열에서 판별.
5. API가 허용하는 날짜 구간으로 나누고 모든 페이지 수집. 2022년부터 현재까지의 과거 제공 범위를 확인하며 제공되지 않는 구간은 누락 사실 기록.
6. 공고번호와 차수/정정 식별자를 보존. 정정/취소 처리, 날짜 기준과 시간대를 명시.
7. 원문과 표본 대조 후 데이터 공개. 부분 수집은 완전 수집으로 표시하지 않음.

## 개발: 연구과제

공식 확인 대상: 경제·인문사회연구회(https://www.nrc.re.kr), 국가정책연구포털 NKIS(https://www.nkis.re.kr).

- 공개 API가 있다는 사실은 아직 확인되지 않았습니다. API 또는 공식 다운로드 제공 여부와 이용 조건을 먼저 확인합니다.
- 소관기관 명단과 기관별 자료 수록 범위를 확인합니다.
- 과제와 연구보고서를 구분합니다. 보고서 목록만 제공되면 과제 전체라고 표시하지 않습니다.
- 연도 기준(과제 수행연도 또는 보고서 발간연도)을 실제 자료 구조에 따라 정하고 화면에 명시합니다.
- 공개 API가 없으면 공식 파일 다운로드나 제공기관 문의를 검토합니다. 무단 수집이나 가상 API 주소로 대체하지 않습니다.

## 공개 데이터 계약

공식 응답을 변환한 뒤 아래 필드를 사용합니다. 실제 API 필드 이름과는 다릅니다.

- kind: research 또는 bids
- status: pending 또는 ready (ready는 전체 수집 완료를 의미하지 않음)
- period: start=2022-01-01, end=2026-12-31 (2026년은 실제 수집 시점까지)
- updatedAt: 수집 시각 ISO 8601
- sources: 공식 출처 이름 배열
- items: id, year, title, org, url을 갖는 배열
- 입찰 items: industryCodes에 문자열 1169 포함

비밀키, 비공개 개인정보, 원본 인증 요청 URL은 저장하지 않습니다.
연구기관 소속, 공고 날짜, 원문 정확성, 수집 완전성은 형식 검사만으로 검증되지 않습니다.

## 운영 계획 (아직 미구현)

명세 및 인증 확인 → 수집기 구현 → 과거 자료 초기 적재 → 원문 대조 → GitHub Actions 정기 수집 → 검증된 JSON만 원자적으로 갱신 → GitHub Pages 배포.
실패 시 이전 정상 데이터를 유지하고 실패를 기록합니다. 수집 실패로 빈 파일을 덮어쓰지 않습니다.

## 로컬 검증

저장소 루트에서:

```sh
node scripts/validate-data.cjs
node --test tests/data.test.cjs
python3 -m http.server 8000 --bind 0.0.0.0
```

JSON fetch를 사용하므로 HTML을 file://로 직접 여는 대신 HTTP 서버에서 확인합니다.
